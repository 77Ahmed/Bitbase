# BitBase Downloader

> Download videos & audio from YouTube, TikTok, Instagram, Twitter/X and 1000+ sites, in your browser.

A full-stack web app with a **Python backend** (FastAPI + yt-dlp) and a modern animated web UI.
Paste a link, pick MP4 or MP3 and a quality, and the file is saved to your device.

## Features

- **Single videos**: preview the title, thumbnail, channel and length, then pick from the qualities that video actually has
- **Playlists & channels (bulk)**: fetch up to 500 videos, search, filter, select a range (e.g. 1–50), and download them one after another
- **Smart link detection**: paste any link and BitBase works out whether it's one video or a playlist
- **MP4 video** up to 4K, or **MP3 audio** at 64–320 kbps
- **Live progress**: real download progress streamed from the server (Server-Sent Events)
- **Download history** saved in your browser
- Contact form, supported-sites page, and a features page
- Unicode filenames (Urdu, Hindi, Arabic… titles are kept)

## Quick start

You need **Python 3.10+** and **Node.js 18+**. Node is used once to build the web UI, and yt-dlp also uses it for YouTube.

```bash
git clone https://github.com/77Ahmed/Bitbase.git
cd Bitbase

python -m venv .venv
# Windows:  .venv\Scripts\activate      Mac/Linux:  source .venv/bin/activate
pip install -r server_py/requirements.txt

python run.py
```

Open **http://localhost:4000**. The first run builds the web UI automatically.

| Command | What it does |
|---|---|
| `python run.py` | Build the UI (first time only) and start the app on port 4000 |
| `python run.py --dev` | Developer mode: backend auto-reload + live UI at http://localhost:3000 |
| `python run.py --build` | Rebuild the UI after you change files in `src/`, then start |
| `pytest` | Run the backend tests (`pip install -r requirements-dev.txt` first) |

> **ffmpeg** (needed to merge HD video + audio and to make MP3s) comes with the `imageio-ffmpeg` package, so you don't have to install it yourself. If ffmpeg is already installed on your system, BitBase uses that instead.

## How it works

```
 Browser (web UI)                         Python backend  (server_py/main.py)
 ───────────────                          ─────────────────────────────────────
 paste link  ──── POST /api/info ───────▶  yt-dlp reads title, thumbnail, formats
             ◀─── video info  /  {isPlaylist: true} → switches to bulk screen

 Download    ──── GET  /api/progress/ID ─▶  live % via Server-Sent Events
             ──── POST /api/download ────▶  yt-dlp downloads → ffmpeg merges/converts
             ◀─── file streamed back ─────  temp file deleted after sending
```

| API endpoint | Purpose |
|---|---|
| `POST /api/info` | Details and available qualities for one video |
| `POST /api/playlist` | All videos in a playlist or channel |
| `POST /api/download` | Download one video/audio file |
| `POST /api/bulk-download/{i}` | Download one item of a bulk selection |
| `GET /api/progress/{jobId}` | Live progress stream |
| `POST /api/contact` | Save a contact message (`server_py/messages.json`) |
| `GET /api/direct` | Download a file in one request, for scripts (needs `key` when `API_KEY` is set) |
| `GET /api/health` | Status: yt-dlp version, ffmpeg, cookies |

Interactive API docs are at **http://localhost:4000/docs** (generated by FastAPI).

## Deploy

### Render (free)

No GitHub connection needed. Render pulls the public repo and builds the `Dockerfile`.

1. In your Render project: **New → Web Service → Public Git Repository**, then paste `https://github.com/77Ahmed/Bitbase`.
2. Set **Language: Docker**, **Branch: main**, **Instance type: Free**.
3. Under **Environment Variables**, add:
   - `API_KEY`: any long random value (Render's **Generate** button works). It protects `/api/direct`.
   - `YOUTUBE_COOKIES` (optional): only if YouTube blocks the server, see below.
4. Under **Advanced**, set **Health Check Path** to `/api/health`.
5. Click **Deploy**. The first build takes ~5–10 minutes, then the site is live at `https://<name>.onrender.com`.

> A public-URL service doesn't redeploy on its own. After pushing changes, open the service and click **Manual Deploy → Deploy latest commit**.
> **Stays awake on the free plan:** Render normally sleeps free services after 15 minutes without visitors. BitBase pings its own `/api/health` every 10 minutes when it runs on Render (it reads Render's `RENDER_EXTERNAL_URL`), so it stays awake. One always-on service uses ~744 of Render's 750 free hours a month. Set `KEEP_AWAKE=0` to turn this off.

### Docker (Railway, Fly.io, any VPS)

```bash
docker build -t bitbase .
docker run -p 4000:4000 bitbase
```

**Railway**: connect the GitHub repo. It reads `nixpacks.toml` and installs everything automatically.

### YouTube blocking your server?

YouTube often asks cloud servers to "sign in to confirm you're not a bot". Other sites aren't affected. BitBase already does three things automatically:

- runs a **PO-token server** ([bgutil](https://github.com/Brainicism/bgutil-ytdlp-pot-provider), included in the Docker image) so requests look like a real YouTube player and HD formats are offered;
- when YouTube blocks a request, it **retries as other YouTube clients** (TV, mobile web, Safari, …) and remembers the one that worked;
- uses **IPv4** for YouTube.

To see which strategies work on your server right now, open `/api/yt-check?key=<API_KEY>`.

If YouTube is still blocked, add cookies from a **throwaway** YouTube account (never your main one):

1. In a private browser window, sign in to YouTube with the throwaway account and play any video.
2. Export the cookies with a browser extension such as *Get cookies.txt LOCALLY* (choose youtube.com, Netscape format).
3. Give them to BitBase in one of these ways:
   - **Render:** service → **Environment** → **Secret Files** → add a file named `cookies.txt` and paste the contents. BitBase reads `/etc/secrets/cookies.txt`.
   - Or paste the contents into a `YOUTUBE_COOKIES` environment variable.
   - On your own computer: save them as `server_py/cookies.txt` (already in `.gitignore`, so **never commit it**).
4. Redeploy, then check `GET /api/health`: it shows `"cookies": true`.

Cookies expire after a few weeks. When YouTube starts failing again, export fresh ones.

Alternatively, set `YOUTUBE_PROXY` to a (paid) residential proxy URL such as `http://user:pass@host:port`. Only YouTube traffic uses it.
